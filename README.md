# Awesome-Critical-Event-Management

### Top Critical Event Management Tools Ecosystem

**Curated List of SaaS/Hosted Platforms & Open-Source GitHub Projects**
*Focused on Critical Event Management, Crisis Management, Emergency Notification, Incident Response & Organizational Resilience*
**Last updated: August 2026**

This repository tracks notable **SaaS/hosted platforms** and **open-source projects** for **Critical Event Management (CEM)**. These tools help organizations detect threats, assess their impact, notify affected people, coordinate response teams, manage incidents, maintain situational awareness, and recover from critical events.

**Examples** include Everbridge, OnSolve, Noggin, AlertMedia, Crises Control, Veoci, BlackBerry AtHoc, Fusion Risk Management, Preparis, Riskonnect, and other emergency management and organizational resilience platforms.

Critical Event Management overlaps with **mass notification, emergency notification, crisis management, incident management, emergency operations centers (EOCs), business continuity management (BCM), disaster response, operational resilience, risk intelligence, employee safety, and public warning systems**.

**Open-source emphasis**: This repository heavily emphasizes open-source software that can be self-hosted and adapted for custom emergency-management workflows. The open-source section includes emergency warning systems, incident-management platforms, computer-aided dispatch, crisis coordination, on-call escalation, situational-awareness boards, notification systems, and supporting infrastructure.

The goal is to provide a practical ecosystem map ranging from **enterprise CEM platforms** to **developer-oriented open-source emergency and incident-management systems**.

Contributions welcome! Open a PR to add/update entries. Keep descriptions factual and link to official sites or GitHub repositories.

## Open-Source GitHub Projects

* **[OpenEWS](https://github.com/open-ews/open-ews)**
  Open-source emergency warning system dissemination platform designed for alerting authorities to distribute warning messages during natural disasters and public emergencies. It supports API-driven dissemination and channels including messaging, IVR, and cell broadcast, and is licensed under MIT.

* **[Resgrid](https://github.com/Resgrid/Core)**
  Open-source computer-aided dispatch, personnel management, AVL, logistics, disaster response, and emergency-management platform for first responders and organizations. Licensed under Apache 2.0.

* **[GoAlert](https://github.com/target/goalert)**
  Open-source on-call scheduling, automated escalation, and notification system. It can automatically engage the appropriate person through channels such as SMS and voice calls and is licensed under Apache 2.0.

* **[Situational Awareness Board](https://github.com/CityOfMonmouth/sitaware)**
  Free, self-hosted emergency alerting and situational-awareness platform designed for smaller emergency-management agencies. Provides alerts, staff notifications, and a shared live incident view.

* **[SCRIBE](https://github.com/nocomp/scribe)**
  Open-source hospital crisis-management platform for multi-site crisis coordination, crisis logs, capacity tracking, transfers, exercises, and emergency workflows. Licensed under AGPL-3.0.

* **[CrisisKit Lite](https://github.com/feiyu23/crisiskit)**
  Open-source crisis-management application focused on rapid crisis-data collection, AI-assisted triage, duplicate detection, dashboards, location intelligence, and emergency coordination. Licensed under MIT.

* **[IncidentRelay](https://github.com/roxy-wi/IncidentRelay)**
  Self-hosted open-source incident-alerting platform providing on-call schedules, alert routing, escalations, reminders, acknowledgements, notification channels, and integrations with monitoring systems.

* **[PageFire](https://pagefire.dev/)**
  Open-source incident-management system providing on-call scheduling, alert escalation, and notifications in a lightweight self-hosted architecture. Uses an MIT license.

* **[Uptime Kuma](https://github.com/louislam/uptime-kuma)**
  Open-source monitoring platform that can provide the detection and alert-generation layer for custom incident-management and emergency-notification systems.

* **[Grafana](https://github.com/grafana/grafana)**
  Open-source observability and visualization platform useful for situational-awareness dashboards, monitoring, alerting, and operational event visualization.

* **[Prometheus](https://github.com/prometheus/prometheus)**
  Open-source monitoring and alerting toolkit useful for detecting infrastructure and operational events that can trigger incident workflows.

* **[Alertmanager](https://github.com/prometheus/alertmanager)**
  Open-source alert-management component for deduplicating, grouping, routing, silencing, and inhibiting alerts before they are delivered to response systems.

* **[Zabbix](https://github.com/zabbix/zabbix)**
  Open-source monitoring and alerting platform that can serve as an event-detection layer in an incident-management architecture.

* **[ntfy](https://github.com/binwiederhier/ntfy)**
  Open-source notification service that publishes messages to phones and desktops using HTTP-based publish/subscribe mechanisms.

* **[Gotify](https://github.com/gotify/server)**
  Self-hosted open-source push-notification server that can be used as a notification backend for custom emergency and incident systems.

* **[Apprise](https://github.com/caronc/apprise)**
  Open-source notification library supporting a large number of notification services and channels, useful for connecting incident systems to different communication endpoints.

* **[ntfy Android](https://github.com/chenxiaolong/ntfy)**
  Open-source ecosystem for self-hosted push notifications that can complement emergency and operational notification systems.

* **[Node-RED](https://github.com/node-red/node-red)**
  Open-source flow-based automation platform useful for building integrations between event sources, notification services, sensors, APIs, and crisis workflows.

* **[Home Assistant](https://github.com/home-assistant/core)**
  Open-source automation platform that can detect events from connected devices and sensors and trigger custom notifications and emergency workflows.

* **[OpenHIM](https://github.com/jembi/openhim-core)**
  Open-source interoperability layer useful when emergency-management systems need to integrate heterogeneous healthcare and operational systems.

* **[OpenStreetMap](https://github.com/openstreetmap/openstreetmap-website)**
  Open geographic-data ecosystem useful for mapping incidents, affected populations, facilities, responders, evacuation areas, and operational assets.

* **[Sahana Eden](https://github.com/flavour/eden)**
  Open-source humanitarian response and disaster-management platform supporting coordination, registries, requests, assets, organizations, and emergency-response workflows.

* **[Open Disaster Management System](https://github.com/)**
  Open-source disaster-management projects across GitHub can provide components for incident tracking, emergency coordination, resource management, and public communications.

### Recommended Open-Source Combinations

**Lightweight Emergency Notification Stack**

`OpenEWS + ntfy + Apprise + Node-RED`

Suitable for organizations that primarily need emergency alert dissemination and flexible notification routing.

**Emergency Operations Stack**

`Sahana Eden + Resgrid + OpenStreetMap + Grafana`

Useful for disaster response, resource coordination, emergency personnel management, mapping, and operational awareness.

**Enterprise Incident-Response Stack**

`Kafka + Prometheus + Alertmanager + GoAlert/IncidentRelay + Grafana`

Useful for organizations building an internal event-detection, escalation, on-call, and operational-awareness platform.

**Community Crisis Stack**

`CrisisKit Lite + OpenStreetMap + ntfy + Node-RED`

Useful for community-driven crisis intake, triage, location awareness, and rapid communications.

**Healthcare Crisis Stack**

`SCRIBE + OpenStreetMap + Grafana + ntfy`

Useful for hospital crisis management, capacity monitoring, incident coordination, and emergency communications.

**Full Open-Source CEM Architecture**

`Kafka/Flink → Event Detection → Incident Management → Situational Awareness → Decision Support → OpenEWS/Notification Layer`

This architecture can approximate many of the major functional layers found in commercial CEM platforms while allowing organizations to control their infrastructure and customize integrations.

## Important Critical Event Management Concepts

A complete CEM system typically combines several capabilities:

* **Threat Intelligence** — Detecting emerging threats before they become critical events.
* **Risk Monitoring** — Continuously monitoring operational, environmental, geopolitical, cyber, and physical risks.
* **Event Detection** — Identifying incidents from sensors, APIs, monitoring systems, reports, and external feeds.
* **Risk Scoring** — Estimating severity, probability, exposure, and potential business impact.
* **Geospatial Intelligence** — Determining where an event is occurring and which people, facilities, assets, or operations are affected.
* **Impact Assessment** — Determining the operational consequences of an event.
* **Mass Notification** — Rapidly notifying employees, responders, customers, or the public.
* **Multi-Channel Alerting** — SMS, voice, email, push notifications, desktop alerts, radio, public-address systems, and other channels.
* **Two-Way Communication** — Allowing recipients to acknowledge alerts, respond to questions, or provide status information.
* **Escalation Management** — Automatically escalating unacknowledged alerts to additional responders.
* **Incident Management** — Tracking incidents from detection through resolution.
* **Emergency Operations Center (EOC)** — Centralized coordination of crisis-response activities.
* **Situational Awareness** — Maintaining a real-time operational picture of an unfolding event.
* **Resource Management** — Tracking personnel, vehicles, equipment, facilities, supplies, and other resources.
* **Business Continuity** — Maintaining critical operations during disruptions.
* **Crisis Management** — Coordinating executive-level decision-making during major events.
* **Disaster Response** — Coordinating emergency response to natural or human-caused disasters.
* **Employee Safety** — Locating and communicating with employees during emergencies.
* **Evacuation Management** — Coordinating evacuation zones, routes, shelters, and affected populations.
* **Public Warning** — Disseminating emergency information to the general population.
* **Cell Broadcast** — Broadcasting alerts to mobile devices within geographic areas.
* **Incident Timeline** — Maintaining an auditable chronological record of events and decisions.
* **After-Action Review** — Capturing lessons learned and improving future response.
* **Business Impact Analysis** — Understanding how disruptions affect critical business processes.
* **Operational Resilience** — Preparing organizations to absorb, respond to, and recover from disruptions.
* **Human-in-the-Loop Response** — Combining automation with human decision-making for high-impact events.
* **AI-Assisted Crisis Management** — Using AI to summarize events, classify incidents, prioritize threats, and recommend response actions.
* **Automation & Orchestration** — Automatically triggering workflows based on event conditions.
* **Interoperability** — Connecting CEM systems with monitoring, GIS, communications, HR, ITSM, security, and emergency-management systems.

## How to Contribute

1. Fork the repo.
2. Add/edit entries in `README.md` (follow the existing format).
3. Include: name, official link or GitHub repository, 1–2 sentence description, and whether it is SaaS/hosted or open-source.
4. Prefer projects with active repositories and meaningful documentation.
5. For open-source projects, accurately identify the primary capability — emergency notification, crisis management, incident response, CAD, situational awareness, on-call, disaster response, or supporting infrastructure.
6. Verify the project's current license before adding it.
7. Submit a PR with a short explanation.

Star the repo if you find it useful!

## Disclaimer

* This is a **community-curated** list — not exhaustive and not an endorsement.
* Critical Event Management overlaps with emergency management, mass notification, business continuity, incident management, public warning, and IT incident response; some projects therefore provide supporting rather than complete CEM functionality.
* Open-source projects vary substantially in maturity, scalability, documentation, licensing, security, and production readiness.
* Always verify the current license, project activity, deployment model, integrations, and operational requirements before adopting a project.
* Emergency notification systems should be tested extensively before being used for life-safety or mission-critical communications.
* Critical-event systems involving sensitive employee, security, medical, or location data should use appropriate privacy, security, access-control, encryption, and governance mechanisms.
* For life-safety applications, organizations should validate notification delivery, redundancy, failover, geographic coverage, and regulatory requirements independently.
